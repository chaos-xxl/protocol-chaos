# 混沌协议 · Protocol Chaos

**你的事情属于你，AI 可以换。**

混沌协议是一份开放协议，定义一个由用户掌握的「事情共同层」：人们跟 AI 助手说起的那些长期的事，比如一次旅行、一门课、一次装修、一个决定、一个长远的愿望。这些事放在用户自己掌握的一个库里，任何兼容的助手都能读、能补充、能把它们连起来，换了助手也还在。

[English](README.md)

> **draft 0.2，2026 年 10 月。** 规范还会变，草案不承诺兼容。欢迎提意见、写实现。

## 五分钟试用

需要 Node.js 20 或更高版本，以及一个能用 MCP 服务端的助手。把参考服务端加到你的助手里，名字用 `protocol_chaos`：

- **Claude Code：** `claude mcp add --scope user protocol_chaos -- npx -y protocol-chaos@0.2`
- **Codex**，写在 `~/.codex/config.toml` 里：

  ```toml
  [mcp_servers.protocol_chaos]
  command = "npx"
  args = ["-y", "protocol-chaos@0.2"]
  ```

- **Claude Desktop、Cursor、Kiro** 等用 JSON 配置的客户端（`claude_desktop_config.json`、`~/.cursor/mcp.json`、`~/.kiro/settings/mcp.json`）：

  ```json
  { "mcpServers": { "protocol_chaos": { "command": "npx", "args": ["-y", "protocol-chaos@0.2"] } } }
  ```

`protocol-chaos@0.2` 跟着这一版草案和它的修复走，以后的草案会是 `0.3`。想从源码跑，就 `git clone`、`npm ci`，命令写成 `node /path/to/protocol-chaos/server/index.mjs`。

然后跟一个助手说一件你在打算的事，比如「我想学街头摄影，不过只能周末去」。再打开另一个助手，或者开一个新对话，问它我说过摄影什么。这件事存在 `~/.protocol-chaos/repository.json` 里，一个普通的 JSON 文件，归你所有。

也请给每个助手装上[接入指南](docs/agent-guide.md#server-instructions)里的常驻指引：MCP 只告诉助手有哪些工具，不告诉它什么时候用。

## 为什么

很多人已经同时用好几个助手：生活一个，工作一个，写代码又一个。每个助手各记各的，可一个人的事不会按助手来分。同一个计划要跟每个新助手再讲一遍，换了工具就丢了。

而且事情不是孤立的。看起来一次性的事，大多不是：一次旅行属于想多看看世界的愿望，一台相机服务于一个爱好，一次搬家牵动全家。混沌协议把这些事（协议里叫 Event）和它们之间的联系，放在属于用户的一个地方。助手来来去去，读的是同一个库，各自用自己的名字往里写。

## 协议定义了什么

协议只规定信封，内容用自然语言：

- **事情（Event）**：标题、状态、进展、要达成什么、要满足的条件、定下来的安排、涉及的人和地方和东西，以及属于哪件更大的事。一件事可以只有一句话：稀疏是常态。
- **用户的原话**：原样保存，永不修改。助手自己推断的要标明是推断、写明依据，以用户的话为准。
- **实体（Entity）**：用户提到的人、动物、东西和地方，包括用户本人，每条陈述只说一件事。
- **修订（Revision）**：每次改动都写明是谁改的、依据的是哪句原话。
- **写入规则**：什么该记、什么不该记，让往同一个库里写的每个助手做法一致。
- **导出和导入**：一个库随时可以整个拿走、搬到别处。

客户端怎么判断一段对话涉及哪些事、怎么排序、什么时候整理，由客户端自己决定。完整规则见 **[PROTOCOL.md](PROTOCOL.md)**（英文）。

## 实现一个服务端

1. 读 [PROTOCOL.md](PROTOCOL.md)。先做 Core 级别；实体、搜索、同步、撤销、远程是可选级别（§12）。
2. 把各项操作做成 MCP 工具（§9.1）：一台电脑用 stdio；几台电脑共用一个库时用 streamable HTTP，每个客户端一个凭证（§9.2）。
3. 跑兼容性测试，不用克隆仓库：

   ```sh
   npx -y -p protocol-chaos@0.2 protocol-chaos-conformance --stdio "node my-server.js --data {tmp}"
   ```

   套件每启动一个服务端，`{tmp}` 就换成一个新的空目录。测试会写数据，所以库不是空的就拒绝运行。在克隆下来的仓库里，`node conformance/run.mjs` 接受同样的参数。

规范的目标是光看它就够写出实现。我们验证过：一个从没见过任何实现的 Agent 只读这份文档写了一个服务端，第一次就通过了当时 40 项 Core 测试中的 39 项；它发现的那处缺口已经补进文档。这个服务端就是这里的参考服务端，`npm test` 会对它跑全部测试。

## 你的数据

- 库属于它的用户。每个合格的服务端都必须让用户导出全部内容、导入到另一个服务端（§8.6），所以用户随时可以带着自己的事离开。
- 参考服务端把库存在你电脑上的一个文件里，不发往任何地方。
- 目前每个接入的助手都能读到全部事情和实体，按客户端分别授权还没设计（§13）。只接入你愿意把整个库交给它的助手。助手读到的内容会进入它的模型上下文，由它的服务商处理。
- 助手被要求永远不记录密码、令牌和证件号码（§7）。

## 现状

draft 0.2 来自每天的使用：作者每天都在用 draft 0.1 的一个实现，几台电脑上的几个助手共用一个库。0.2 留下了使用中证明有用的部分，去掉了从没用上的部分。那个实现就是 npm 上的 `protocol-chaos` 包，它不在这个仓库里，正在改到这一版。

还没解决的问题包括：按客户端分别授权、跨应用认出同一个人、删除，以及多人共有的事（[§13](PROTOCOL.md#13-open-issues)）。
