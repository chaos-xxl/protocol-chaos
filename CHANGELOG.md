# Changelog

The specification and the `protocol-chaos` package, which holds the reference server and the conformance tests, are listed together. A package version follows the draft it implements: 0.2.x implements draft 0.2.

## Unreleased

From two more real imports of the same memory files, and a check of invented notes extended to ten checks:

- **One more call after the parts puts together what they wrote apart.** Each part is read on its own, so a larger aim and its parts could be written apart. In the background, a last call is shown the matters the import started under no larger matter, with the words each rests on, and the other open matters, and names links. A link is written only for a matter the import started, and only when the reason the model gives is in the words of the child or of the parent; the link rests on those words. In the first real run without that condition, two of the four links it made rested on nothing the words said, only on a shared theme; with it, none did.
- **The model's JSON is mended before it is asked again.** A quote mark left unescaped inside a string, a line break inside a string and a comma before a closing bracket are mended; the log says when. In one real import an answer that would not parse cost a second call.
- **The rules say what else is not a matter, and what is a plan.** A style or a direction the user keeps to, and what they believe or have thought through (a judgment, a concept, a method), are not matters. A project's list of next steps is its plan, not a matter each. When the notes state an aim and name matters already written as its parts, the aim is a matter and those go under it. Finished matters include a review passed or a renovation done.
- **Old memory files: their projects, not their to-dos.** A part names the files not changed for 90 days or more, whose steps may be done or dropped since; their projects and aims are written as matters and their steps kept in the plan.
- **Claude Code memories of type `feedback` or `reference` are left out**: they say how to work or where things are, never what is to be done. In a real import, two of them became matters.
- The plan's estimate includes the last call.

## protocol-chaos 0.2.7 (2026-11-18)

From importing a real set of memory files (8 files, about 24,000 characters), whose largest aim was missing from the result:

- **A quote the model retyped is found.** The model's copy of a sentence is looked for without the spaces, markdown marks and end marks it added or dropped, and with dashes, quote marks and full-width forms counted as one: a line copied with a full stop the notes do not have, `3-5` for `3–5`, or `8000元` for `8000 元` no longer leaves its matter out. What is written is the sentence as the notes word it, no longer the model's copy.
- **The rules say three things more.** An aim, plan or target written among background facts (a profile's career or finances, say) is a matter. A sentence that only shares a word or a theme with a matter is not about it. An existing matter can be given a parent when the repository shows it under none.
- **A later part can put a matter an earlier part started under a larger one.** When the notes name the larger matter only further on, the import links the two, grounded on the words about it; matters the repository held before the import are not moved.
- The import's log says, for each part, how many matters were written and how many left out and why (no sentence of the notes, no title, or a write refused), still without words.
- **The organizer's answer is decoded as one stream.** A character whose bytes came in two chunks of the agent's output was read as broken characters (`���`): in the second real import, one title. Long answers, as an import's are, came in several chunks; a fold's answer is short, so it was hit only rarely.

## protocol-chaos 0.2.6 (2026-11-18)

- **`init` connects OpenCode, OpenClaw, Claude Desktop, GitHub Copilot and Pi.**
  - OpenCode: an entry in its global settings (`opencode.jsonc` or `opencode.json`), in the shape OpenCode 1.x and 2.x both read; OpenCode shows the server's instructions itself.
  - OpenClaw: `openclaw mcp set`, and the instructions in the workspace's `AGENTS.md`, since MCP tools sit behind OpenClaw's tool search; `uninstall` runs `openclaw mcp unset`.
  - Claude Desktop: an entry in `claude_desktop_config.json`, written only while the app is closed, because it writes its whole settings file back when it saves a setting. Its chat shows the model neither a server's instructions nor a local file of them, so the server runs with the new `--instructions-in-tools`, which puts the instructions at the start of the description of `context_pack`.
  - GitHub Copilot: an entry in `~/.copilot/mcp-config.json`, read by Copilot CLI and VS Code's Copilot agent, with the instructions in `~/.copilot/copilot-instructions.md`, and one in VS Code's user `mcp.json` for its local chat.
  - Pi (0.99 and later): an entry in `~/.pi/agent/mcp.json` with the tools declared to the model, and the instructions in the context file Pi reads; an older Pi is left out with the reason.
- **JSON settings files keep their comments.** `init` reads and edits them with `jsonc-parser`, so a file with comments or trailing commas (common in OpenCode and VS Code) is no longer refused; only a file that cannot be read as JSON is. This adds `jsonc-parser` as a dependency.
- **One agent `init` cannot add to no longer stops the others**: it is left out, with the reason, and the rest are connected.
- The import also reads OpenCode's global `AGENTS.md`, OpenClaw's `MEMORY.md`, `USER.md` and newest 30 daily notes, Copilot's `copilot-instructions.md` and the memories of VS Code's Copilot chat, and Pi's context file.
- The import's report, and `import --undo`, no longer count a matter the import started among the matters the repository held already when a later part of the notes added words to it.

## protocol-chaos 0.2.5 (2026-11-18)

- **`init` connects Kiro and Cursor.** Kiro gets a `protocol_chaos` entry in `~/.kiro/settings/mcp.json` (the IDE and Kiro CLI share it) and, since it does not show a server's instructions to its model, a global steering file with them, included in every conversation. Cursor gets an entry in `~/.cursor/mcp.json` and the instructions as a skill, `~/.cursor/skills/protocol-chaos/SKILL.md`, whose description carries the main rule. The JSON files keep their indentation and everything else in them; `uninstall` puts them back byte for byte, or, when they were edited since, takes out only the entry. A settings file that is not plain JSON is refused. Neither can organize in the background yet.
- **Importing other assistants' memories**, so that a new repository does not start empty. `npx protocol-chaos import` (and `init`, once) reads the memory files and standing instructions of Claude Code, Codex, Gemini CLI, Hermes, Kiro, Cursor and DeepSeek Harness, leaves out rules for using this repository, hides keys, tokens and long numbers, and shows which files it would read and leave out, what it would cost in tokens and time, and where the text goes, before it asks. It runs in the background with the organizer's model, one call per part of about 6,000 characters; only matters resting on sentences of the notes, copied exactly, are written, as the actor `importer`, with `authorized_external` words naming their file, parents first. Where `init` could not ask, the next assistant does: a connection from the computer is offered the tool `memories_import`, and the instructions say so, while an import waits to be offered, runs, or waits to be reported; when it is done, the assistant shows the report and the tree of open matters, the new ones marked. Without an organizer, the assistant in the conversation reads the parts itself. A desktop notification says when a background import is done; `import --status` shows the report and `import --undo` cancels the matters it started. See [server/README.md](server/README.md#importing-other-assistants-memories). With `deepseek-flash`, an import of invented notes from three assistants found the six matters they hold, put a part under its long-term goal, and made no matter of who the user is or how to answer ([eval/import/](eval/import/README.md)).
- **A folder that holds only skills is no longer taken for an installed agent.** `npx skills add` makes a skills folder for many agents at once, installed or not. `init` used to take a Codex or DeepSeek Harness folder as a sign of the agent even when it held nothing but skills; now it says so and leaves that agent out.
- **Where nobody organizes in the background** (only Kiro or Cursor connected, or `--organizer none`), each `event_note` an agent connected by `init` makes is answered with a second text after the receipt, reminding its model to bring the matter's fields up to date itself. The receipt itself is unchanged.
- `init` no longer looks for an organizer on every run when none of the connected agents can be one.
- `uninstall` also removes the empty `runtime` folder it left behind in the repository's folder once no agent is connected.

## protocol-chaos 0.2.4 (2026-11-17)

- **`npx protocol-chaos init`** connects Claude Code, Codex, DeepSeek Harness and Hermes on one computer (macOS or Linux) to one repository, asking which (all by default; `--yes`, `--only`, `--dry-run`). It installs the server under the repository's folder with a launcher that apps started from the desktop can run, and gives each agent an MCP server named `protocol_chaos` under its own name with the `writer` tools. Codex does not show a server's instructions to its model as instructions, so `init` also writes them into Codex's `AGENTS.md`. For Hermes it runs the server over HTTP on `127.0.0.1` at login (launchd or systemd), issues Hermes a token, writes both into Hermes's `.env`, adds the `protocol_chaos` MCP server and installs the plugin. Agents read the directory themselves; nothing is added to a turn before the model answers. Every change is recorded and every file edited is backed up: `npx protocol-chaos uninstall` puts the files back byte for byte, and `npx protocol-chaos doctor` starts the server through the launcher and checks each agent's entry. Running `init` again repairs a launcher whose Node.js or server is gone. Agents that already have a `protocol_chaos` server are left alone, and `--yes` will not connect others to a separate repository when one of them uses a server elsewhere. See [server/README.md](server/README.md#installer).
- **Organizing in the background.** When `init` has chosen an organizer, the server queues the words of every `event_note` and a detached process folds them into their matter with one call to the organizer's model, grounded on those words, once the assistant has finished its turn: the per-message part of organizing that the Hermes plugin does after each answer, now for every agent. The organizer is the first connected of DeepSeek Harness (`dsh --profile headless`), Claude Code (`claude -p`, `haiku`, a spending cap per call) and Codex (`codex exec`); `init --organizer` picks another or `none`. A daily sweep at 04:00 folds what nobody folded and calls no model when nothing changed. `protocol-chaos organize --status` shows the last runs; the log keeps ids and token counts, never words. DeepSeek Harness runs read-only, without tools, session history or the session-log upload, with the keys saved in the app and `deepseek-flash` with thinking off. With it, the fold passes the 12 checks of [eval/organize/](eval/organize/README.md), and an end-to-end run folded 11 sentences in about 2 seconds and 1,400 tokens each.
- **`--client <name>` over stdio.** The instructions name the assistant, and writes as anyone else are refused (`ACTOR_MISMATCH`), as over HTTP; the version rule of remote connections does not apply.
- **Tool groups.** The reference server can offer a connection only some of its tools: `--tools` takes groups (`read`, `record`, `fields`, `links`, `history`, `sync`, `entities`, `owner`) and profiles (`assistant`, `writer`, `all`), and over HTTP each client can have its own (`clients add <name> --tools …`, `clients tools <name> …`). The default is `all`, so existing clients see no change. An assistant that only records needs four tools (about 3,500 characters of definitions) instead of fourteen (about 23,700 before this release). Draft 0.2 §9.1 now says that a server may do this.
- **Shorter tool definitions.** Every tool's description and input schema says what it does, the rules that matter when calling it and what it returns, and no more: the fourteen together are about a fifth shorter. `progress.timestamp` says it is UTC ending in `Z` and may be left out, the cause of most of the rejected writes in the experiment's pilot runs.

## Hermes plugin

Hermes installs it from this repository; it is not in the npm package. `npx protocol-chaos init` installs it for a Hermes on the same computer.

- **0.3.2 (2026-11-17): no matters are added to a turn unless you ask for it.** A new setting, `related`, is `off` by default: the model reads the overview, where every line now carries its matter's id, and opens the matters a message is about itself through the `protocol_chaos` MCP server. Picking by the words a message shares with titles also picks matters it is not about (on a labeled set built on a real store, something was added for about one in four unrelated messages), and the model decides better. `related: on` keeps the 0.3.1 behaviour.
- **0.3.1 (2026-11-09)**, from an audit of the author's own repository (139 matters). The overview in the system prompt is now a map of every open matter: one line each, ordered by the most recent change anywhere beneath a matter, and where the latest stand while there is room; dormant matters are counted instead of listed. 0.3.0 ordered the matters by the last change of the topmost one and cut from the end: with 114 open matters it listed 50, 16 of them dormant, and left out 9 of the 15 that changed most recently. When not every line fits, the most recently changed are kept, each with the matters it sits under, and the rest are counted.
- **0.3.0 (2026-11-06)**, from a week of daily use. One episode of a long-lived matter (a breakdown, one trip) is recorded on a part of its own, titled with when it happened, and the structure update leaves out of a long-lived matter what holds only for one episode; it now sees the matter's parents and open parts. A note by an assistant is folded as a fact when it records what the assistant did, and as an inference only when it says so. Scheduled jobs get no overview in their system prompt. The log has one line per turn with the time the plugin took before the model answered, and one per model call with its time and tokens. The organizer skill cleans a broad matter after moving an episode's words into a part, and renames titles with relative times.
- **0.2.0 and 0.2.1 (2026-10-22 and 10-23): a plugin for [Hermes Agent](https://github.com/NousResearch/hermes-agent)**, in [integrations/hermes/](integrations/hermes/protocol-chaos/README.md). Before the model answers, an overview of the user's open matters is in the system prompt, and the matters a message names, picked on the client from the directory's titles, are read by id and added to the turn. After it answers, the recording model decides whether the message changes a matter, the words are recorded with `event_note`, verbatim, and then folded into that matter's fields with `event_record_expression`, grounded on those words and read with the last few messages of the conversation. The server never receives the messages (§10). Includes an organizer skill for draft 0.2, offered as the automation blueprint `protocol-chaos:organizer`, and passes `hermes plugins validate`. Hermes installs it from this repository; it is not in the npm package.

## protocol-chaos 0.2.3 (2026-10-22)

- **The reference server implements the Remote level (§9.2).** `--http [host:]port` serves MCP streamable HTTP at `/mcp`. Each assistant gets its own token (`protocol-chaos clients add <name>`), kept only as a hash and revoked at once by `clients remove`. Over HTTP a client writes only as itself (`ACTOR_MISMATCH` otherwise), the writes that change fields or parents need `expectedVersion` (`VERSION_REQUIRED`), and requests from a browser page are refused. Plain HTTP is served only on a loopback address; elsewhere the server needs `--tls-cert` and `--tls-key`, or a TLS reverse proxy in front. See [server/README.md](server/README.md#remote).
- Every conformance test that can run over `--url` passes over HTTP; the tests now run that way too.

## Draft 0.2 and protocol-chaos 0.2.0 (2026-10-20)

The first public draft, and the first release of the reference server.

- **Specification.** One flat Event document: title, state, progress, facts, refs, parents and metadata. A single `state` with six values, writer rules (§7), and the principle that clients decide on their own side what to send (§10). Everything is defined for interoperability only: matching, storage and models are left to implementations. [Appendix A](PROTOCOL.md#appendix-a-changes-from-draft-01) lists every change from draft 0.1.
- **Conformance tests.** 75 tests over MCP, covering every requirement on servers at the levels Core, Entities, Search, Sync, Undo and Remote.
- **Reference server.** Core, Entities, Search, Sync and Undo over MCP stdio, written from the specification alone. The repository is one JSON file in the export format, shared safely by several assistants on one computer. `npx -y protocol-chaos@0.2`.

## Draft 0.1 (protocol-chaos 0.1.0-alpha.1 to 0.1.0-alpha.11, September to October 2026)

The working draft behind the author's daily use, with several assistants on different computers sharing one repository. It was implemented by the 0.1.0-alpha versions of `protocol-chaos`, which are still available as `protocol-chaos@alpha`, and is replaced by draft 0.2.
