# Changelog

The specification and the `protocol-chaos` package, which holds the reference server and the conformance tests, are listed together. A package version follows the draft it implements: 0.2.x implements draft 0.2.

## protocol-chaos 0.2.4 (2026-11-17)

- **`npx protocol-chaos init`** connects Claude Code, Codex, DeepSeek Harness and Hermes on one computer (macOS or Linux) to one repository, asking which (all by default; `--yes`, `--only`, `--dry-run`). It installs the server under the repository's folder with a launcher that apps started from the desktop can run, and gives each agent an MCP server named `protocol_chaos` under its own name with the `writer` tools. Codex does not show a server's instructions to its model as instructions, so `init` also writes them into Codex's `AGENTS.md`. For Hermes it runs the server over HTTP on `127.0.0.1` at login (launchd or systemd), issues Hermes a token, writes both into Hermes's `.env`, adds the `protocol_chaos` MCP server and installs the plugin. Agents read the directory themselves; nothing is added to a turn before the model answers. Every change is recorded and every file edited is backed up: `npx protocol-chaos uninstall` puts the files back byte for byte, and `npx protocol-chaos doctor` starts the server through the launcher and checks each agent's entry. Running `init` again repairs a launcher whose Node.js or server is gone. Agents that already have a `protocol_chaos` server are left alone, and `--yes` will not connect others to a separate repository when one of them uses a server elsewhere. See [server/README.md](server/README.md#installer).
- **Organizing in the background.** When `init` has chosen an organizer, the server queues the words of every `event_note` and a detached process folds them into their matter with one call to the organizer's model, grounded on those words, once the assistant has finished its turn: the per-message part of organizing that the Hermes plugin does after each answer, now for every agent. The organizer is the first connected of DeepSeek Harness (`dsh --profile headless`), Claude Code (`claude -p`, `haiku`, a spending cap per call) and Codex (`codex exec`); `init --organizer` picks another or `none`. A daily sweep at 04:00 folds what nobody folded and calls no model when nothing changed. `protocol-chaos organize --status` shows the last runs; the log keeps ids and token counts, never words. DeepSeek Harness runs read-only, without tools, session history or the session-log upload, with the keys saved in the app and `deepseek-flash` with thinking off. With it, the fold passes the 12 checks of [eval/organize/](eval/organize/README.md), and an end-to-end run folded 11 sentences in about 2 seconds and 1,400 tokens each.
- **`--client <name>` over stdio.** The instructions name the assistant, and writes as anyone else are refused (`ACTOR_MISMATCH`), as over HTTP; the version rule of remote connections does not apply.
- **Tool groups.** The reference server can offer a connection only some of its tools: `--tools` takes groups (`read`, `record`, `fields`, `links`, `history`, `sync`, `entities`, `owner`) and profiles (`assistant`, `writer`, `all`), and over HTTP each client can have its own (`clients add <name> --tools …`, `clients tools <name> …`). The default is `all`, so existing clients see no change. An assistant that only records needs four tools (about 3,500 characters of definitions) instead of fourteen (about 23,700 before this release). Draft 0.2 §9.1 now says that a server may do this.
- **Shorter tool definitions.** Every tool's description and input schema says what it does, the rules that matter when calling it and what it returns, and no more: the fourteen together are about a fifth shorter. `progress.timestamp` says it is UTC ending in `Z` and may be left out, the cause of most of the rejected writes in the experiment's pilot runs.

## Hermes plugin

Hermes installs it from this repository; it is not in the npm package. `npx protocol-chaos init` installs it for a Hermes on the same computer.

- **0.3.2 (2026-11-17): no matters are added to a turn unless you ask for it.** A new setting, `related`, is `off` by default: the model reads the overview, where every line now carries its matter's id, and opens the matters a message is about itself through the `protocol_chaos` MCP server. Picking by the words a message shares with titles also picks matters it is not about (on a labeled set built on a real store, something was added for about one in four unrelated messages), and the model decides better. `related: on` keeps the 0.3.1 behaviour.
- **0.3.1 (2026-11-09)**, from an audit of the author's own repository (139 matters). The overview in the system prompt is now a map of every open matter: one line each, ordered by the most recent change anywhere beneath a matter, and where the latest stand while there is room; dormant matters are counted instead of listed. 0.3.0 ordered the matters by the last change of the topmost one and cut from the end: with 114 open matters it listed 50, 16 of them dormant, and left out 9 of the 15 that changed most recently. When not every line fits, the most recently changed are kept, each with the matters it sits under, and the rest are counted.
- **0.3.0 (2026-11-06)**, from a week of daily use. One episode of a long-lived matter (a breakdown, one trip) is recorded on a part of its own, titled with when it happened, and the structure update leaves out of a long-lived matter what holds only for one episode; it now sees the matter's parents and open parts. A note by an assistant is folded as a fact when it records what the assistant did, and as an inference only when it says so. Scheduled jobs get no overview in their system prompt. The log has one line per turn with the time the plugin took before the model answered, and one per model call with its time and tokens. The organizer skill cleans a broad matter after moving an episode's words into a part, and renames titles with relative times.
- **0.2.0 and 0.2.1 (2026-10-22 and 10-23): a plugin for [Hermes Agent](https://github.com/NousResearch/hermes-agent)**, in [integrations/hermes/](integrations/hermes/protocol-chaos/README.md). Before the model answers, an overview of the user's open matters is in the system prompt, and the matters a message names, picked on the client from the directory's titles, are read by id and added to the turn. After it answers, the recording model decides whether the message changes a matter, the words are recorded with `event_note`, verbatim, and then folded into that matter's fields with `event_record_expression`, grounded on those words and read with the last few messages of the conversation. The server never receives the messages (§10). Includes an organizer skill for draft 0.2, offered as the automation blueprint `protocol-chaos:organizer`, and passes `hermes plugins validate`. Hermes installs it from this repository; it is not in the npm package.

## protocol-chaos 0.2.3 (2026-10-22)

- **The reference server implements the Remote level (§9.2).** `--http [host:]port` serves MCP streamable HTTP at `/mcp`. Each assistant gets its own token (`protocol-chaos clients add <name>`), kept only as a hash and revoked at once by `clients remove`. Over HTTP a client writes only as itself (`ACTOR_MISMATCH` otherwise), the writes that change fields or parents need `expectedVersion` (`VERSION_REQUIRED`), and requests from a browser page are refused. Plain HTTP is served only on a loopback address; elsewhere the server needs `--tls-cert` and `--tls-key`, or a TLS reverse proxy in front. See [server/README.md](server/README.md#remote).
- Every conformance test that can run over `--url` passes over HTTP; the tests now run that way too.

## Draft 0.2 and protocol-chaos 0.2.0 (2026-10-20)

The first public draft, and the first release of the reference server.

- **Specification.** One flat Event document: title, state, progress, facts, refs, parents and metadata. A single `state` with six values, writer rules (§7), and the principle that clients decide on their own side what to send (§10). Everything is defined for interoperability only: matching, storage and models are left to implementations. [Appendix A](PROTOCOL.md#appendix-a-changes-from-draft-01) lists every change from draft 0.1.
- **Conformance tests.** 75 tests over MCP, covering every requirement on servers at the levels Core, Entities, Search, Sync, Undo and Remote.
- **Reference server.** Core, Entities, Search, Sync and Undo over MCP stdio, written from the specification alone. The repository is one JSON file in the export format, shared safely by several assistants on one computer. `npx -y protocol-chaos@0.2`.
